> 写于 2026-10-23。这个文档只管"怎么玩、什么时候能做什么"，人物和文字以 `06_文字.md` / `web/src/data/script.json` 为准，机位以 `web/src/world/cameras.json` 为准。
> 逻辑已实现成纯函数模块 `web/src/game/logic.js`（不依赖 Three.js），线索位置和解锁条件在 `web/src/data/clues.json`，测试 `web/src/game/logic.test.js`：

## 一、状态

一局的全部状态就是下面这几个字段（`initialState()`）：

| 字段 | 含义 |
|---|---|
| `phase` | `play` 探索中 → `sword` 三字齐、播拔剑 → `ending` 结果卡 |
| `gateOpened` | 推过门，之后才算进入大奥 |
| `scaleIntro` | 药贩子说过"天秤响了"（只说一次，第一次拿到任何线索时） |
| `met.asa / kame / utayama` | 见过谁 |
| `has.E1 … E6b` | 拿到了哪些证物 |
| `lit.kata / makoto / kotowari` | 形 / 真 / 理 哪个亮了 |
| `pans.left / right` | 天秤两盘上现在放着什么 |
| `ending` | `A` 或 `B`，在"理"亮起的那一下决定 |
| `counters` | 放错次数、对话次数，给结果卡和数据用 |

没有血量、没有计时、没有失败。唯一的"惩罚"是放错时天秤摇一下回弹。

## 二、解锁规则（什么时候能做什么）

| 动作 | 条件 | 结果 |
|---|---|---|
| 推门 | 无 | 进走廊，药贩子说 `gate` |
| 拾 E1 彩线 | 在走廊 | 得 E1 |
| 看壁画得 E2 | 走到壁画前按"看" | 得 E2 |
| 阿龟给 E3 | 第一次和阿龟说话 | 得 E3，之后只剩 `after_e3` |
| 翻簿子得 E4 | **先和歌山说过话** | 得 E4，之后歌山说 `after_e4` |
| 捞井得 E5 | **形和真都亮了** | 否则药贩子说 `well_before`，井不响 |
| 拾 E6a 线轴 / 开抽屉得 E6b | 进阿雪的空房 | 两件都能拿，拿了一件天秤就不再催另一件 |
| 阿浅给空房提示 | 真亮了且还没拿 E6 | 说 `hint_room`；拿了 E6 后说 `after_e6` |
| 放证物 | 证物在手、对应盘空着、它对应的字还没亮 | 放上 |
| 称 | 两盘都有 | 见第三节 |
| 拔剑 | 三字齐 | `phase = sword`，播视频 |

房间和中庭没有锁，玩家可以乱走；锁只锁在"井"这一处，因为捞井是理的开头，前面没弄清就捞会让故事顺序乱掉。

## 三、天秤

天秤是引导、界面、核心机制三合一，规则（2026-10-28 推演后改过）：

**只催"当前这个字"的线索，同一个字先催左盘再催右盘，指向其中最近的一个。**

- "当前这个字" = 形、真、理里第一个没亮的。在找形的时候，哪怕走到阿雪空房门口，天秤也不理抽屉里的回信；理的阶段先催井（本体），捞到了再催空房的两件。这样引导顺序和故事顺序一致，玩家不会被天秤带去走廊尽头提前翻东西。
- 左盘先催：彩线 → 壁画，阿龟 → 簿子，井 → 空房。
- 这个字剩下的线索只差"见过某人"才解锁时（簿子要先见歌山），天秤指向那个人（目标写成 `@utayama`）。原来这一段天秤完全安静，推演里从女中房走到歌山房 12 米一声不响，正是最容易迷路的时候（10-28 改）。
- "可发现" = `clues.json` 里 `requires` 全满足。井在形真亮之前不可发现，所以站在井边天秤也不响，这和药贩子那句"还不是时候"是一致的。
- 推门前不催。
- 只算水平距离，**半径 6 米**（走廊 13 米，8 米时一进门就晃个不停）；振幅 = 1 − 距离 / 6，三档铃声在 0.35 / 0.65 / 0.9 处，对应离线索 3.9 / 2.1 / 0.6 米，只在**变近一档**的那一刻响一次（`stepUp`）。降档有 0.08 的回差，在门槛附近来回走不会反复响。
- 对话、配对覆盖层打开时不更新天秤。
- 阿龟的 E3 没有坐标，用阿龟的站位。
- 空房的两件不被天秤催，但随时能拿；提前拿了也只是配对时多一个选项。

配对：

- 证物自带 `pan`（左 / 右），界面只允许放到对应盘，所以玩家不用猜左右，只猜"哪两件是一对"。
- 两盘放满自动称。对上：亮字，播 `pairs[].line` 和药贩子那一字的台词；第三个字亮时追加 `all_three`。错：说 `wrong`，两盘清空，证物回到手里，计一次错。
- 已亮的字对应的证物不能再放，避免玩家把 E1 反复放上去。
- E5 配 E6a 还是 E6b 决定结局，**放上去就定**，没有确认步骤。另一件如果也拿了，结果卡末尾提一句（`endings[].other`）。

## 四、防卡关

`nextStep()` 返回当前推荐的下一步 id，顺序就是第五节的路线。用法建议：

- 玩家一段时间没有任何进展（没拿到新证物、没亮新字），右下角天秤旁边淡入一行提示，再过一段换更直白的一句。等待秒数由 `hintDelay(id)` 给：教学性的步骤（推门、拾线、看壁画、每次"该开天秤了"）45 / 90 秒，探索性的步骤 90 / 150 秒。推演里每一步理想用时最长 28 秒，45 秒已经是两倍。
- "进展"应该包括：拿到证物、说过话、称亮一个字、**走进一间新房间**（说明玩家在探索，不要催）。
- 提示文字在 `script.json` 的 `hints` 表里（文案线写的），键如下：

| id | 什么时候 | 提示方向 |
|---|---|---|
| `open_gate` | 还没推门 | 门 |
| `pick_E1` | 走廊里有线 | 地上 |
| `look_mural_E2` | 有线没画 | 墙上的壁画 |
| `weigh_E1_E2` | 两件在手 | 打开天秤 |
| `talk_kame_E3` | 形亮了 | 女中的房间 |
| `talk_utayama` | 有信没簿 | 歌山的房间 |
| `read_ledger_E4` | 见过歌山 | 她桌上的簿子 |
| `weigh_E3_E4` | 两件在手 | 天秤 |
| `fish_well_E5` | 真亮了 | 中庭的井 |
| `talk_asa_hint` | 捞了井没见阿浅 | 去问阿浅 |
| `search_yuki_room` | 阿浅提过空房 | 走廊尽头右手那间 |
| `weigh_E5_E6` | 两件在手 | 天秤 |
| `watch_sword` / `save_card` | 收尾 | |

## 五、攻略

> 给玩家看的一页纸版本在 `13_攻略.md`（操作、地图、一步步、配对表、卡住怎么办）。这一节保留开发用的路线分析。

### 推荐路线（一周目，理想下限 2.6 分钟，实际预计 6 到 10 分钟）

1. **门口**：推门。
2. **走廊**：顺着天秤走，地上拾 **E1 彩线**；走到左墙壁画（约走廊中段）按"看"，得 **E2**。打开天秤，E1 放左、E2 放右，**形**亮。
3. **女中的房间**（走廊右手第一间）：先和阿龟说话，她直接给 **E3 家书**。顺便和阿浅说话听证言（不给东西，但以后要靠她）。
4. **歌山的房间**（右手第二间）：先和歌山说话，再翻桌上的簿子得 **E4**。E3 左、E4 右，**真**亮。
5. **中庭**（左手）：天秤这时才会指向井。捞井得 **E5**。
6. **阿雪的空房**（右手第三间，走廊尽头）：角落 **E6a 线轴**，抽屉 **E6b 回信**，两件都拿。不知道这间房在哪就回去问阿浅。
7. 打开天秤：E5 左，右盘放 **E6a 得结局 A**（母亲的手），放 **E6b 得结局 B**（没写完的"我很好"）。放上去就定。
8. 拔剑过场，结果卡，保存。

### 两个结局

| 结局 | 右盘 | 结果卡 |
|---|---|---|
| A | E6a 木线轴 | 阿雪舍不得的，是缠线的那双手。 |
| B | E6b 没写完的回信 | 阿雪舍不得的，是那句没写完的"我很好"。 |

两件都拿了再称，结果卡会多一句提到另一件。想看另一个结局要再开一局（熟路 3 到 4 分钟）。

### 最短路线（速通）

推门 → E1 → E2 → 称 → 阿龟 → 歌山 → 簿子 → 称 → 井 → 空房拿一件 → 称。11 次互动，0 次对话浪费，不用和阿浅说话（她只给提示）。

### 会走弯路的地方

- 先去井：药贩子说"还不是时候"，天秤也不响。回去把前两件事做完。
- 不和歌山说话直接翻簿子：文机和歌山只隔 0.64 米，站到簿子前按 E 大概率是"看"而不是"说话"。逻辑层这时返回 `talkFirst: "utayama"`，界面应直接先播她的对话再让翻，玩家不用自己找她。
- 在空房只拿一件就走：没关系，天秤不会催另一件，但结果卡就不提另一件。
- 把 E3 和 E2 放一起：错，摇一下回弹，不扣东西。左盘永远是"痕迹 / 人证 / 物怪本体"，右盘是"原样 / 物证 / 执念物"。

## 六、还没定的

1. 结局后要不要提供"从井边重来"（只重做第 6 到 8 步看另一个结局）。加了会降低二周目门槛，但也降低选择的分量。我倾向不加，让第二局短一点就够。
2. 提示文字（第四节的 `hints` 表）由另一个对话写进 `script.json`。
3. `logic.js` 接进查看器（待办第 9 项）：天秤界面读 `scaleSignal`，对话读 `talk`，配对读 `put / weigh`。

### 请用户实际玩一遍时重点看

1. 第一次开天秤（Tab）之前有没有迷茫：如果有，提示 45 秒是否够早。
2. 歌山房里站到簿子前按 E 的手感：是先对话还是弹"看完请出去"。
3. 一局玩完看表：和 6 到 10 分钟的估计差多少。
4. 天秤铃声会不会烦：13 次是上限，觉得多就把档位改成两档 `[0.4, 0.85]`。
