# 游览版方案：药郎在原作地点里走走看看

> 写于 2026-10-29。探案版（手鞠案）已归档，在 GitHub `Duamixu1/strange_kitty` 的 `v0-探案版` 标签。这份是推翻重来后的游览版方案。**10-29 已拍板：第二个地点改用万屋**（见第八节），下文第四节以前写坂井家的地方按万屋读。
> 新版本另开 `web/tour.html`，`web/game.html` 和 `web/src/game.js` 保持探案版原样。
> 要你决定的事集中在最后一节。

## 一句话

不做玩法。药郎从一张绘卷总地图出发，走进原作各篇事件发生的地方，在里面随便走、随便看，碰到观景点弹出一张说明卡，可以拍照。场景骨架用 Blender 脚本拼的日式建筑积木，世界实验室（World Labs）泼溅只留给每个地点最出彩的一两间房。

## 一、原作调研

### 1. 到底有几季

查过日文和英文维基、电影资讯站、Netflix 相关报道，结论：**《モノノ怪》TV 动画只有一季**，没有第二季。

| 作品 | 年份 | 形式 | 篇目 |
|---|---|---|---|
| 《怪～ayakashi～》（Ayakashi: Samurai Horror Tales） | 2006 | TV 选集，11 集，三个故事 | 四谷怪谈（1~4 集）、天守物语（5~8 集）、**化猫（9~11 集）**。只有化猫篇是药郎的故事，算前传 |
| 《モノノ怪》 | 2007 | TV，12 集，一季 | 座敷童子（1~2）、海坊主（3~5）、のっぺらぼう（6~7）、鵺（8~9）、化猫（10~12） |
| 《劇場版モノノ怪 唐傘》 | 2024-07-26 | 电影三部曲第一部 | 大奥 |
| 《劇場版モノノ怪 第二章 火鼠》 | 2025-03-14 | 第二部 | 大奥 |
| 《劇場版モノノ怪 第三章 蛇神》 | 2026-05-29（Netflix 全球 2026-09-29） | 第三部，三部曲完结 | 大奥 |
| 新项目 | 2026-07 公布 | 只放了 PV，形式和时间都没公布 | 第三位药郎「乾の剣」，配音新木宏典 |
| 舞台剧 | 2023 化猫、2024 座敷童子、2026 前日譚〜二首女〜 | 真人舞台 | 不在这次范围 |

你说的"第一季、第二季"，最可能是把 2006 年的化猫篇当第一季、2007 年的 TV 当第二季。中文圈管整个系列叫"怪化猫"，一般认为名字就是从"怪～ayakashi～ 化猫"来的。也有人把电影当续作，但那是三部电影，不是 TV 季。

下表里"标志性画面"主要来自维基的介绍，我没有逐集看过。**带"待看片确认"的是推测**，做之前你挑几帧参考截图放进 `assets/concept/ref/`（只放本机）。

两点发现：

- **三部电影全在大奥。** 大奥一个地点就能连起三部电影，以后每部各加一两间房就行，不用开新地点。
- **2006 化猫和唐傘都有一口井。** 可以当成两个地点之间的呼应，总地图上把两口井画在同一条线上。

### 3. 推荐顺序

三条标准各打 1 到 3 星：**还原难度**（星越多越好做）、**积木复用**（能用同一套日式建筑积木搭多少）、**粉丝认得**。

| 顺序 | 地点 | 还原 | 复用 | 认得 | 理由 |
|---|---|---|---|---|---|
| 1 | **大奥**（唐傘 / 火鼠 / 蛇神） | ★★★ | ★★★ | ★★★ | 已有五块泼溅和可走图；三部电影都在这，Netflix 刚上完结篇 |
| 2 | **坂井家**（怪～ayakashi～ 化猫） | ★★★ | ★★★ | ★★★ | 一层武家屋敷，几乎就是积木的样板间；药郎第一次登场的地方，"怪化猫"这个名字的来源；有井，和大奥呼应 |
| 3 | 万屋（座敷童子） | ★★ | ★★★ | ★★★ | TV 第一集，认得的人最多；要多层和楼梯，装饰也比坂井家繁复 |
| 4 | 笛小路家（鵺） | ★★ | ★★★ | ★★ | 积木全能用；单色水墨画风反而能让总地图有变化；剧情偏冷门 |
| 5 | そらりす丸（海坊主） | ★★ | ★ | ★★★ | 海和巨眼认得的人多，海面用一张全景天空就够；但船要单独建一套积木 |
| 6 | 地铁（化猫 TV） | ★★ | ★ | ★★★ | 车厢本身好做（一个盒子加座椅），但大正风要另起一套积木，车厢窄，镜头受限 |
| 7 | 牢房（のっぺらぼう） | ★ | ★★ | ★★ | 不单独做地点，挂在某个地点里当一个观景点，或者以后做成"心象"特别关卡 |

**推荐先做两个：大奥（已有）+ 坂井家。** 坂井家选它而不选万屋，是因为它是平房，正好拿来把积木做扎实；万屋要楼梯和多层，放第三个做，到时候积木已经稳了。

## 二、低成本混合方案

### 1. 现在的花费

一块泼溅 = 全景图 40 积分（Tripo 的图片模型）+ World Labs 生成 1500 积分。大奥五块花了约 7700。照这个做法，一个地点 4 到 5 块，七个地点就是五万上下，不现实。

### 2. 几种手段对比

| 手段 | 积分 | 我这边的工作量 | 画面能到什么程度 | 镜头自由度 |
|---|---|---|---|---|
| **A. World Labs 泼溅**（现做法） | 每块 1540 | 半天（工具都有：`worldlabs_gen.py` → `spz_clip.py` → `room_place.py` → `walkmap.py`） | 最好。全景拍摄点 5 米内和概念图一模一样，笔触、纹样、壁画全在 | 差。离拍摄点远了糊，离墙 1 米内全是虚影 |
| **B. Blender 积木**（柱、梁、障子、襖、榻榻米、屋檐、廊、地面、井、石灯笼） | 0 | 积木库第一次 2 到 3 天；之后每个地点拼 1 到 2 天 | 干净的平涂 + 描边 + 世界空间纹样（现成的 `toon.js`），横平竖直；缺原作那种手绘的满屏细节，要靠襖绘和壁画贴图补 | 完全自由，贴墙也不糊 |
| **C. 单张 360 全景当天空 / 窗外景** | 每张 40 | 1 小时 | 远处的东西（天空、海、庭院远山、城下町）和概念图一样，没有视差 | 不受影响（它永远在远处） |
| **D. 360 全景当"定点观景"**：药郎走到某个点，切成站在全景中心只能转头看 | 每张 40 | 半天 | 一个点上画面最好，和泼溅原点看到的一样 | 只能原地转头，不能走 |
| **E. Blender 渲染贴图**：把积木场景渲染成图，用来做远景、襖绘底稿、总地图 | 0（直接用）/ 40（渲染后再让图片模型按色板重画一遍） | 半天 | 直接用偏 CG；重画后和概念图一个味道，构图还是我们控制的 | 同 C |
| **F. 一块泼溅多处复用**：比如女中房那块（一间标准榻榻米房）在坂井家里当一间普通座敷，离线调色相 | 0 | 半天（离线改 .spz 颜色，同 `spz_clip.py` 的路子） | 和原泼溅一样；但同一间房在两个地点出现，熟悉的人能认出来 | 同 A |

几点说明：

- 40 积分的全景图和概念图走 Tripo 的图片模型，1500 走 World Labs，是两个账户。Tripo 余额 10-28 记的是 16260 左右；World Labs 的余额待办里没记，歌山房那次卡过一回积分，换了新密钥才出的。
- 积木和泼溅放在同一个画面里会有画风断层（一边硬边平涂、一边手绘笔触）。所以**一个区块只用一种技术**，区块之间用现成的拉门擦除转场切换，玩家看不到两种同时在屏幕上。最后一层和纸后期也会把两边往一起拉。
- Spark 有个老坑：运行时改泼溅的集合会把整套泼溅搞挂（`03_推进路线.md` 第八节）。所以**换地点 = 换页面参数重新加载**（`tour.html?loc=sakai`），一个地点内的泼溅在加载时一次定好。

### 3. 每个地点花多少

一个地点按 4 个区块算：

| 做法 | 组成 | 积分 |
|---|---|---|
| 全泼溅（现做法） | 4 块泼溅 | 约 6200 |
| **混合（推荐）** | 积木骨架 3 块 + 重点泼溅 1 块 + 全景天空 / 窗外 2 张 + 襖绘、壁画 2 张 | **约 1700**（1540 + 160） |
| 纯积木 | 积木 4 块 + 全景天空 2 张 + 襖绘 2 到 4 张 | 约 160 到 240 |

建议坂井家先按"纯积木"做，看效果再决定那一块重点泼溅花不花。值得花泼溅的房间，坂井家是藏嫁衣的密室或婚礼的大座敷，万屋是顶层那间大房间。

### 4. 镜头策略

关键风险：自由跟随镜头在泼溅里离墙 1 米内全是虚影。办法是**不同区块用不同的镜头规则**，现有的 `camera_director.js` 已经有固定、轨道、挂点三种，再加一种跟随就够：

| 区块类型 | 镜头 | 做法 |
|---|---|---|
| 积木区块 | **自由跟随** | 鼠标拖转，镜头到角色之间打一条球形射线，撞到墙就拉近；镜头和角色之间挡着的柱子、襖做半透明（网点溶解，平涂风格里看着像淡出）。积木不糊，贴墙也没问题 |
| 泼溅房间 | **半固定："站在拍摄点看"** | 泼溅在全景拍摄点往四周看都是清楚的，所以镜头只在拍摄点周围半径约 1.5 米的安全圈里滑动（安全圈再扣掉离墙 1.2 米的范围），转头去对着角色。角色可以走遍整间房，镜头不跟着贴墙走 |
| 泼溅里的狭窄处 | 固定机位 | 角色走进安全圈照不到的角落，切到预设的固定机位（现有的分区机位做法） |
| 定点观景（手段 D） | 只转头 | 角色隐去或站在镜头前，玩家原地环视 |
| 车厢、船舱这类窄空间 | 轨道 | 镜头沿车厢中线前后滑，和走廊现在一样 |

另一个办法是泼溅房间全部固定机位，像原作的构图那样一格一格切。更稳，但"随便走走看看"的感觉会弱。我建议先做安全圈，安全圈效果不好再退回固定机位。

## 三、结构

```
绘卷总地图
 └─ 地点（大奥、坂井家……）      一个地点 = 一次页面加载 tour.html?loc=xxx
     └─ 区块（走廊、座敷、厨房、井边……）  区块之间用拉门转场
         └─ 观景点                  走近出提示，按 E 弹说明卡；P 拍照
```

- **总地图**：MVP 用 2D 绘卷，一张横向长卷，左右拖着看，各地点画成小插图，点一下进入。没开放的地点画上去但是灰的，让人知道后面还有。绘卷图可以用 Blender 把积木摆成微缩场景渲染底稿，再让图片模型按色板重画（约 40 到 80 积分）。
- **地点数据**：每个地点一个 JSON（`web/src/data/tour/sakai.json` 之类），写区块、门、出生点、观景点、镜头规则、用到的泼溅和积木布局。
- **观景点**：位置、朝向、说明卡文字、推荐的拍照机位。说明卡写"这是哪、原作里这里发生过什么"，**用自己的话，一两句，不抄台词，不剧透结局**。
- **拍照**：隐藏界面、可选几个滤镜（夜色、雨、褪色）、存 PNG。探案版结尾卡已经有存 PNG 的代码，可以搬。
- **积木布局用文字画平面图**：一格半间（0.91 米），一个字符一格，比如 `#` 墙、`.` 榻榻米、`=` 廊板、`D` 拉门、`W` 井。你看片时也能自己画一张，我照着生成。可走图直接从平面图算，不用再跑 `walkmap.py`。

### 地点 JSON 格式（10-29 定，`tour.html` 按这个读）

一个地点一个文件 `web/src/data/tour/<地点id>.json`（场景线填）。区块的可走格子、出生点、观景点、楼梯口由 `kit_build.py` 出的 `<积木名>_walk.json` 提供（格式见 `16_积木平面图格式.md` 第四节），地点 JSON 只管"有哪些区块、怎么连"。

```json
{
  "id": "wanya", "name": "万屋",
  "start": "genkan",                     // 进地点先到哪个区块
  "background": "#2A2A4E",               // 画面外的底色（雨夜可以更深）
  "camera": { "dist": 3.2, "pitch": 0.32, "fov": 50 },   // 跟随镜头默认值，区块里可以再覆盖
  "zones": {
    "genkan": {
      "name": "玄关",                    // 左上角状态栏和说明卡顶上显示
      "kit": "wanya_genkan",             // → assets/processed/kit/wanya_genkan.glb + data/tour/wanya_genkan_walk.json
      "spawnYaw": 3.14,                  // 出生时药郎朝向（0 = 面向 +z）
      "exits": [ { "stair": 0, "to": "top", "arrive": 0, "label": "上楼" } ],
      "camera": { "dist": 2.6 }          // 可选，小房间镜头近一点
    },
    "top": { "name": "顶层大座敷", "kit": "wanya_top", "exits": [ { "stair": 0, "to": "genkan", "arrive": 0, "label": "下楼" } ] }
  }
}
```

- **出口**：`stair` 是本区块 walk 文件 `stairs` 里的第几个（平面图上的 `U`），`to` 去哪个区块，`arrive` 落在那个区块的第几个楼梯口。走到 `stand` 附近自动拉门转场；到了以后站在门前 0.6 米、背对门，离开门口再回来才会再触发。地面上有出口标签，点了自己走过去。
- **观景点**：平面图上的 `1`~`9`。地面上浮一个"観"，走近按 E 或点标签，弹说明卡。说明卡文字在文案线的 `web/src/data/tour/text.json`：`{ "<积木名>.<数字>": { "title": "…", "body": "…" } }`，比如 `"wanya_top.1"`。没写的显示"说明卡待写"。
- **覆盖**：区块里写了 `spawn`、`views`、`stairs`、`height` 就不用 walk 文件里的；`walkRect: [x0, x1, z0, z1]` 可以不要 walk 文件，直接用矩形当可走范围（测试用，例子 `web/src/tour/fixtures/test_corridor.json`）。
- **配角站桩**（10-30 定）：区块里写 `"npcs": [ { "id": "asa", "model": "processed/asa_posed.glb", "height": 1.46, "pos": [x, z], "yaw": 弧度, "clip": "idle" } ]`。只摆着、播待机（起点错开），不对话；药郎绕着走（半径 0.45 米挡住），镜头也不会穿过去。`height` 是包围盒高度（含发饰），阿浅 1.46、阿龟 1.42、歌山 1.57，和探案版一致。例子在 `fixtures/test_ooku_splat.json` 的女中房。
  - **动起来**（10-31）：配角条目可以再加 `"idles": ["动作名", …]`（站着时每隔 8~16 秒随机播一个一次性动作，播完回待机，`"gap": [8, 16]` 可改）和 `"patrol": [[x, z], …]`（从 `pos` 出发沿折线来回走，`"speed"` 默认 0.7 米/秒，到头停 `"pause"` 默认 3 秒；药郎靠近 1.1 米就停下转身看他，走开 2 秒后接着走）。巡逻要模型里有 `walk2_k` / `walk_k`，没有的话是待机姿势平移过去。路线上每一点都要在可走图里，不要穿过观景点、出口和到达点。例子：`test_ooku_splat.json` 女中房的阿龟。
- **泼溅区块**（10-29 定，游4 按这个做；例子 `web/src/tour/fixtures/test_ooku_splat.json`）：
  - 泼溅写在**地点**上，不写在区块上：`"splats": [ 条目, … ]`，条目和 `cameras.json` 的 `layout.splats` 一样（`name`、`quality`、`scale`、`position`、`yawDeg`）。进地点时全部加载、之后不再动（Spark 运行中改显示 / 位置会掉成 0 个点），所以一个地点的几块泼溅要在同一个坐标系里，换区块只换镜头和可走范围。
  - 区块可走图：`"walk": "<名>"` 读 `data/tour/<名>_walk.json`（场景线从探案版 `data/walkmap.json` 复制过来，带 `floor` 地面高度的话药郎会贴着走）；几个区块共用一张图时用 `"walkClip": [x0, x1, z0, z1]` 只留自己那块，进出一律走出口转场。不写 `kit` 就不加载积木。
  - 镜头 `"camera": { "mode": … }`：
    - `"circle"` 安全圈：`center: [x, z]`（全景拍摄点，就是泼溅的 position 的 x、z）、`r` 半径（默认 1.5）、`margin` 离墙至少多远（默认 1.2，窄房间改小）、`h` 镜头高度（默认 1.5）、`dist` 想离药郎多远。镜头在圈里滑、转头对着药郎；药郎走到圈里时镜头让到圈的另一边。
    - `"rail"` 轨道：`a: [x, z]`、`b: [x, z]` 线段，`back` 离药郎多远，`h`。药郎在端头附近、身后退不够时换到前面回头拍。走廊用这个。
    - 任何模式都能加 `"fixed": [ { "rect": [x0, x1, z0, z1], "pos": [x, y, z], "look": [x, y, z] } ]`：药郎走进矩形就切到这个机位（`look` 不写就看药郎）。安全圈照不到的角落、门口用这个。
    - `fov` 可以每个区块单独写（走廊 42，房间 50）。
  - 已知：房间门口那一段，泼溅门外被裁掉了，镜头从房间中间看门口时背景是糊的（测试图 `shots/tour_test_ooku_splat_maids_跟随*.jpg`），每间房要在门口加一个 `fixed` 机位，或者把到达点往里放。

页面：`tour.html` 不带参数是总地图（占位，游5 的图到了再换）；`tour.html?loc=<id>` 进地点，`&zone=<区块>` 直接进某个区块。验收：`tools/tour_shots.sh <地点>` 拍每个区块四个方向的跟随镜头 + walk 文件里的验收机位；`tour.html?loc=<id>&selftest=1` 自己跑一遍"走到观景点、开关说明卡、走进出口、转场、按 W 走"，结果打在控制台。

能从探案版直接搬到 `tour.html` 的：药郎模型和弹簧骨（`character.js`、`spring.js`）、着色和后期（`style/`）、碰撞和点击寻路（`collision.js`、`pathfind.js`）、镜头调度（`camera_director.js`）、大奥五块泼溅和 `walkmap.json`。不搬的：天秤、证物、对话、逻辑层（`game/`）。

## 六、第一步：风险试验

**最大的风险是积木看起来像廉价卡通渲染，配不上原作。**（`03_推进路线.md` 第一节的风险 1 换了个形式又回来了。）这件事不先验证，后面整个混合方案都是空的。

**做法：在大奥走廊拼一段积木版，和现有泼溅版并排对比。**

1. 写 `tools/kit_build.py`：Blender 脚本生成第一批积木（柱、梁、长押、襖、天花格、廊板、地毯、行灯基座），尺寸按半间网格，导出 GLB。
2. 按 `cameras.json` 里走廊的尺寸（宽 6 米、长 13.2 米、高 5.5 米）拼一段一样大的积木走廊。两侧墙面的画直接用已经出过的 `scenes/03_走廊_左墙.png`、`04_走廊_右墙.png` 裁成襖绘贴上去，**不花积分**。
3. 开一个只用来对比的页面（不碰 `game.html`），同一套着色、描边、纹样、和纸后期，药郎站在同一个位置。
4. 从同样的 4 个机位各截一张：走廊入口一点透视、药郎正侧面、贴近左墙 0.8 米、回头看门口。最后一张是故意让泼溅版出虚影的位置。
5. 用 `tools/shot_compare.py` 拼成一张对比图，再加一张预告片参考帧（`ref_04s_走廊_大奥主廊.jpg`）放在一起。

**怎么判断**：

| 结果 | 结论 |
|---|---|
| 积木版和泼溅版放一起，一眼像同一部片 | 混合方案成立，坂井家按纯积木开工 |
| 积木版明显单薄，但加了襖绘以后能接受 | 成立，但每个地点要多准备几张襖绘、壁画（每张 40） |
| 积木版怎么调都像别的游戏 | 混合方案不成立，退回"少量地点、全泼溅、半固定镜头"，地点数砍到三四个 |

预计 1 到 2 天，不花积分。

### 试验结果（2026-10-29，第一轮）

对比图 `assets/processed/shots/kitcmp_对比_积木vs泼溅.jpg`（顶上预告片参考帧，下面四个机位，左积木右泼溅）。没花积分。

- 怎么做的：`tools/kit_textures.py` 从 02~05 号概念图裁墙画、尽头扇面门洞、近端木门，程序画地毯、廊板、紫幔、行灯纸罩、红提灯；`tools/kit_build.py`（Blender）用参数化积木拼走廊，出 `assets/processed/kit/ooku_corridor_kit.glb`（25 种材质，13 万面）；`web/kit_compare.html` 同一套卡通着色、描边、和纸，药郎同位置同姿势；`tools/kit_shots.sh kit|splat` 用无头 Chrome 拍四个机位（内置浏览器 WebGL 被禁时也能拍），`tools/kit_compare_sheet.py` 拼图。
- 积木版：线条干净，贴墙 0.8 米（机位 3）照样清楚，药郎和场景的描边是一套，放在一起不跳。弱点是比泼溅版和预告片**单薄**：天花的串珠和格梁太稀、墙前面的层次只有一层幔，墙画是一整张平面，近看能看出是贴图。
- 泼溅版：远看更满、更像预告片，但机位 3 左半边全糊，机位 4 两侧墙也偏软。
- 结论：落在判断表的**第二档**：积木版单薄，但贴上襖绘以后能接受，混合方案成立。天花和墙前的层次还能靠加积木补，不花积分。
- 顺带改了：`style/post.js` 的外轮廓阈值按表面斜度放大，贴地平视时地板不再被整片涂黑（探案版的 game.html 也受益）。泼溅走廊实际宽约 5 米（walkmap 可走 ±1.9），不是 cameras.json 里写的 6 米，积木版按 5 米做。
- 还没做：积木版天花加密（串珠更大更多、加垂挂的彩球串）、墙前加第二层幔和吊挂的扇子；万屋需要的积木（障子、襖、榻榻米、楼梯口）还没开始。
