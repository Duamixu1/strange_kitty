# 怪化猫二创小游戏：实现方案

> 参考视频：『劇場版モノノ怪 唐傘』特別予告 -表の巻-（https://www.youtube.com/watch?v=dYJ1mx7601E）
> 写于 2026-10-23。工具：Tripo + Blender + Three.js，UE 只在明确需要时才上。

## 一、这个片子的视觉到底是什么

把它拆成可以复刻的规则，后面所有素材都照这几条走：

| 要素 | 片中表现 | 我们的做法 |
|---|---|---|
| 纸 | 整个画面蒙一层和纸纹理，颗粒固定在"屏幕"上，不随镜头动 | Three.js 全屏后期：和纸贴图叠加（overlay/multiply），加轻微暗角 |
| 色 | 大面积平涂，饱和但不脏：朱红、群青、金、墨绿、胭脂 | 定一张 8 色主色板写进 canon，所有贴图只用这 8 色 |
| 线 | 有描边，但不是黑线，是深褐/藏青的"彩线" | 后期描边（法线+深度边缘检测），描边颜色可调，默认深褐 |
| 纹样 | 市松、麻叶、青海波、七宝铺满衣服和拉门 | 做成平铺贴图库，在 Blender 里贴到衣服和拉门上，Tripo 不负责出纹样 |
| 空间 | 像纸戏/立体书：一层层平面叠出景深，镜头常是固定的正侧面或斜 45° | 固定机位 + 分层视差，大奥走廊用模块拼 |
| 光 | 几乎没有真实光照，靠色块和纹样本身出层次 | 卡通着色（2 到 3 阶），不开实时阴影，关 PBR |

**结论：难点不在模型，在着色和后期。** 这正好是 Three.js 自己写 shader 就能做的事，不需要 UE 的真实光照。

## 二、引擎选择：Three.js，不用 UE

| | Three.js | UE5 |
|---|---|---|
| 发布 | 一个链接点开就玩，和你的视频内容联动最顺 | 网页端没有官方导出，要么下载客户端，要么 pixel streaming 租服务器 |
| 画风 | 平涂 + 描边 + 纸纹全是 shader 和后期，几十行代码 | 强项是真实光照，这片子恰好不要 |
| 素材链 | Tripo 直接出 GLB，Three.js 直接读，省掉转 FBX 这步 | 要进 FBX、重建材质 |
| 代码 | Claude 直接写 TS，改完刷新即看 | C++/蓝图，迭代慢 |

UE 只在两种情况下考虑：你以后想做桌面高配版，或者想用 Niagara 做超华丽的退魔特效。退魔那段过场我建议**用 Blender（Eevee + Grease Pencil）渲成视频**，游戏里播放，比 UE 省事而且更像 2D 动画。

## 三、玩法：一桩原创小案子，沿用"形・真・理"

原作规则：药贩子必须知道物怪的 **形**（它是什么）、**真**（发生了什么事）、**理**（执念是什么），才能拔出退魔之剑。这天然就是一个侦探探索游戏的三个收集目标。

为了不复述电影剧情，故事用原创的"番外"：人物和舞台用片里的（药贩子、阿浅、阿龟、大奥走廊），物怪换成一个我们自己设计的小物怪（候选：行灯、镜、手鞠）。

流程（一局 15 到 20 分钟）：

1. **开场**：药贩子走到大奥门前，和纸标题卡。
2. **探索**：走廊 + 一间房 + 中庭，点击或 WASD 移动。药贩子腰上的**天秤**靠近线索会颤动响铃，这是引导。
3. **问话**：阿浅、阿龟、歌山各有一段对话树，每人藏一个线索，拼出 形 / 真 / 理。
4. **拔剑**：三者齐了，剑上封印解开，"形、真、理、揃いました"，播放退魔过场。
5. **结尾卡**：物怪消散，药贩子离开。

状态机就是：探索 → 形 ✓ → 真 ✓ → 理 ✓ → 拔剑 → 结束。和霍格沃茨 `docs/04` 的写法一样。

## 四、素材清单（先做"一条走廊"这一个场景）

| 类别 | 素材 | 产出方式 | 数量 |
|---|---|---|---|
| 角色（绑骨） | 药贩子（主角，走/待机/拔剑）、阿浅、阿龟 | Tripo 概念图 → image-to-model → 自动绑骨 | 3 |
| 角色（静态） | 歌山、2 个背景女中 | Tripo，不绑骨，站桩 | 3 |
| 物怪 | 原创小物怪（本体 + 消散形态） | Tripo 出本体，Blender 做形态键 | 1 |
| 场景模块 | 走廊段、拐角、拉门（开/关）、柱子、畳房间、中庭、井 | Tripo 出单件，Three.js 按 JSON 布局拼 | 7 |
| 道具 | 天秤、退魔之剑、药箱、行灯、唐伞堆 | Tripo | 5 |
| 贴图库 | 和纸纹理、市松/麻叶/青海波/七宝平铺图、8 色色板 | 自己画或程序生成，不走 Tripo | 1 套 |

约 19 个模型。按霍格沃茨的经验每个重做约 35 积分，预留 2 到 3 次返工，Tripo 积分准备 1500 左右。

**风格一致性**（和霍格沃茨一样的教训）：

- 先出 3 张主参考：药贩子正面三视图、走廊全景、色板。所有后续生成都挂这 3 张做参考。
- 全程只用一个图片模型，canon 写进 `tools/scenes.json`。
- 每批出完排成一排看漂移，再进 Blender。

## 五、角色的两个坑和对策

1. **Tripo 出的脸是 3D 脸，不是动画脸。** 对策：固定机位 + 卡通着色遮掉大半；药贩子脸上的妆用概念图投影贴图；实在不行，脸做成一块贴图平面（格斗游戏常用的做法）。
2. **纹样会被 Tripo 烘成一团糊。** 对策：概念图阶段就让衣服纯色，纹样在 Blender 里按 UV 贴平铺图，再烘成一张平涂贴图。

次要人物如果 3D 效果不好，直接做成**纸片人**（带描边的立牌），在这个画风里反而更像原作。

## 六、分阶段

| 阶段 | 做什么 | 产出 | 验收 |
|---|---|---|---|
| 0 设定 | 画风规则、色板、主参考图、原创物怪设定、剧本和对话 | `docs/02_设定.md`、`assets/concept/` | 三张主参考摆一起看着像一部片 |
| 1 素材 | 复制霍格沃茨 `tools/tripo_gen.py`，改清单，出概念图再出模型 | `assets/tripo_raw/*.glb` | 排队预览图里比例、风格不漂 |
| 2 整理 | 复制 `blender_process.py`，改成输出 GLB（Draco 压缩）而不是 FBX，贴纹样、烘平涂 | `assets/processed/*.glb` | 单个模型 < 3 MB |
| 3 着色 | Vite + three + postprocessing：卡通材质、描边、和纸后期；拿一段走廊先跑通 | 能在浏览器看到"像片子"的一帧 | 截图和参考图并排对比 |
| 4 玩法 | 场景 JSON 布局、移动、天秤引导、对话系统、形真理状态机 | 能从开场玩到拔剑 | 自己完整玩一遍 |
| 5 过场和收尾 | Blender 渲退魔过场、标题卡、字体（日文 Shippori Mincho，中文思源宋体）、音效 | 完整一局 | 首屏加载 < 30 MB |
| 6 上线 | Cloudflare Pages，和霍格沃茨同一套 | 链接 | 手机也能开（不保证性能） |

阶段 3 要放在阶段 4 前面：画风不像，后面做再多玩法也白搭。建议素材只先出"走廊段 + 药贩子"两个，把着色跑通再批量出其他。

## 十、补充（2026-10-23）：场景改用 World Labs 生成，Tripo 只做角色和道具

试过了：拿 `02_走廊全景.png` 喂给 World Labs（Marble 1.1，1580 积分，9 分钟），直接得到一个能走进去的 3D 走廊（高斯泼溅 .spz + 碰撞网格 .glb + 360 全景图）。脚本 `tools/worldlabs_gen.py`，查看器 `web/`（Vite + three + Spark），截图在 `assets/worldlabs/corridor_v1/shots/`。

| | 结果 |
|---|---|
| 好的地方 | 原始机位周围 4 到 5 米内细节很高，平涂 + 和纸 + 描边的画风原样保住；地毯、行灯、布幔、灯笼全是立体的；自带碰撞网格可直接走 |
| 差的地方 | 离原点 10 米以上开始拉丝、糊；镜头背后和侧墙上的壁画是它自己"脑补"的，人物和概念图不一样；天花的饰物变成了重复星纹 |
| 代价 | 泼溅不是普通网格：不能套我们的卡通着色和描边，但原图已经是这种画风，所以不需要；和纸后期仍可在屏幕空间叠上去 |

**路线调整：**

- 场景走 World Labs：一张概念图 → 一个可走的"房间"。走廊这种长空间拆成 2 到 3 段，每段一个 world，段与段之间用拉门过场切换，玩家活动范围限制在原点 5 米内。
- 角色和道具仍走 Tripo + Blender + 卡通着色，放进泼溅场景里。
- 碰撞用 `collider.glb`，角色脚底贴地用它的 `metric_scale_factor`（这次是 1.003，基本就是米）。
- 还没试：多图输入（`multi-image`，带方位角）可能让侧墙和背面按我们的概念图来，而不是脑补；下次出走廊时先出左右墙和回头的概念图再一起喂。

### 多图输入试验（corridor_v2，2026-10-23）

四张图（正面 0°、右墙 90°、回头 180°、左墙 270°）一起喂，1600 积分。对比图 `assets/worldlabs/对比_v1_vs_v2.jpg`。

| | v1 单图 | v2 四图 |
|---|---|---|
| 正对 ±90° 的墙 | 脑补的人物 | **按我们的概念图来了**：左墙是脸壁画，右墙是扇子蝴蝶 |
| 回头 | 脑补 | 尽头是我们画的木门 |
| 45°、135° 的斜墙 | 脑补 | 还是脑补（绿衣男人），四张图之间没有覆盖 |
| 脚下和身后的地面 | 完整 | **缺了**：全景图下半截是一片褐色糊，因为三张侧面图取景太近，几乎没拍到地面 |
| 远处 10 米 | 糊 | 糊，一样 |
| metric_scale_factor | 1.00 | 0.76（四张图的透视不一致，它把尺度估小了） |

结论：多图能控制墙面内容，但输入图必须像"站在同一点用同一镜头转圈拍"：侧面图要从走廊中央拍，墙离 4 到 5 米，地面和天花都在画面里。下一次两条路选一条：

1. 重出左右墙图，取景拉远、带地面天花，再加两张 45° 斜视图补缝（4 张上限内只能放 4 张，所以斜视图替换回头图，或者分两次生成）。
2. 直接让图片模型出一张等距柱状 360 全景图（以 02_走廊全景 为参考），`is_pano=true` 喂进去，一次覆盖所有方向。更省积分，优先试这个。

### 360 全景图输入试验（corridor_v3，2026-10-23）

用图片模型（chat_image_2.5_sunburst，3840x1920，40 积分）以正面图和三张墙面图做参考出一张等距柱状全景图 `scenes/06_走廊_360全景.png`，`tools/pano_seam.py` 查接缝（边缘色差比值 2.3，24 像素环绕渐变修到 19），`--pano` 喂给 World Labs，1500 积分。三版对比：`assets/worldlabs/对比_v1_v2_v3.jpg`。

| | v1 单图 | v2 四图 | v3 全景图 |
|---|---|---|---|
| 墙面内容 | 脑补 | ±90° 和回头按图，斜墙脑补 | **全部按图**，斜 45° 也连续 |
| 地面 | 完整 | 身后缺失 | **完整**，低头能看到地毯花纹 |
| 它输出的全景 | 自己编的 | 下半截糊 | 就是我们的输入图，一模一样 |
| 碰撞网格范围 | 宽 20 m，长 78 m | 宽 15 m，长 80 m | **宽 4 m，长 9 m**（-2.2 到 6.6） |
| 可走范围 | 原点 5 m 内清晰 | 同 v1 | 整个盒子都清晰，但 6.6 m 处就是尽头墙 |
| 积分 | 1580 | 1600 | 1500 + 全景图 40 |

结论：**全景图输入是正解**，内容零脑补。代价是空间尺度由全景图里的透视决定，这张全景图把尽头画得太近，Marble 就把走廊理解成一个 4x9 米的小盒子，远端的扇形墙是一块平背景。

对策（写进待办）：

1. 在 Three.js 里把泼溅整体放大 1.5 倍（宽 6 米、长 13 米），比例看起来更像走廊，玩家活动范围仍限制在原点附近。
2. 长走廊按方案拆段：每段一张全景图，段与段之间用拉门切换；出全景图时让尽头画得更远更小，Marble 会估出更长的空间。
3. 以后所有房间都走"概念图 → 360 全景图 → 查接缝 → World Labs"这条链，一个房间约 1540 积分。
