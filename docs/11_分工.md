### 2. 不要和探案版混在一起

1. **探案版的文件冻结，不改**：`web/game.html`、`web/src/game.js`、`web/src/game/`、`web/src/ui/overlay.js`、`web/src/world/graybox.js`、`web/src/world/cameras.json`、`web/src/data/script.json`、`clues.json`、`docs/04~07`、`docs/13_攻略.md`。游览版要用里面的东西，**复制到 `web/src/tour/` 再改**，不要在原文件上改。
2. **游览版的新文件放在固定位置**：页面 `web/tour.html`，代码 `web/src/tour/`，地点数据 `web/src/data/tour/`，文档从 `14_` 往后编号。
3. **共用模块改了要保证探案版还能跑**：`web/src/style/`（着色、后期）、`spring.js`、`props.js`、`collision.js`、`pathfind.js` 两边都在用，改完打开 `game.html` 看一眼。
4. **待办只写在"游览版"那一节**，编号带"游"字；探案版那一节不再加东西、不再改状态。
5. **旧的探案版会话（第二节表里的链接）不再派活**，游览版的活只找上面这四个带 w 的会话。

### 3. 协作规则（沿用）

1. 待办表只有一张，事项开头写线名，做完改状态写日期；改之前先重新读最新版。
2. `tour.html` 只由总指挥改：其他线把成果放在自己的文件里，在待办里写"可以接了"，总指挥接进来验收。
3. 花积分前先说：Tripo、World Labs、图片模型开跑前说清楚花多少。
4. 画风一致：出图挂 `assets/concept/00_色板.png` 和相关主参考图，同一个图片模型，一批出完排一排检查。
5. 截图验收：内置浏览器的 WebGL 被禁时，用无头 Chrome。游览页拍图 `tools/tour_shots.sh <地点>`（等到页面存的收工标记才停，默认最多等 300 秒），自测 `tools/tour_selftest.sh <地点> …`（15 项）；积木对比 `tools/kit_shots.sh`。开发服务器 `npm run dev --prefix /Users/duami/socialmedia/mononoke-game/web`，地址用 `http://[::1]:5173/`。

1. **待办表只有一张**：`docs/02_待办.md`。新加的条目在事项开头写【线名】（如【场景】），做完改状态写日期。改之前先重新读一遍最新版，只改自己那几行，避免几个对话互相覆盖。
