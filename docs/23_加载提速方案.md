# 23 加载提速方案（11-06，用户："目前整个游戏的加载还是很慢，思考一套优化加载速度的方案"）

> 前情：游31 已做过三轮（并行下载、后台预取隔壁、精简版模型、配角进场后再下、进门前三页铺垫、发布时压图）。
> 5 Mbps 下七处首次 7~10 秒，但用户手机上进そらりす丸要两三分钟。这份方案先把时间花在哪量清楚，再分四档给路线。

## 一、时间花在哪（11-06 实测线上 dist）

**几个结构性的事**
- 积木 glb 没有 draco（`kit_build.py` 直接写 glb）：笛小路家雪庭 4.2 万三角 2.3 MB，gzip 后 0.5 MB；压了能到 0.15 MB 左右。
- 配角每个 4.4~5.5 万三角、0.33~0.52 MB；地铁 24 个人站着，就是 7.8 MB。
- 贴图 252 张（207 张 PNG），每处要发 55~77 个请求；GitHub Pages 的缓存只给 10 分钟（`cache-control: max-age=600`），过了 10 分钟每个文件都要回源问一次"变没变"，国内到 GitHub 一次往返几百毫秒，60 个文件光问就是十几秒；换地点时药郎、道具、程序也要再确认或重下。
- **根本原因：网站在 GitHub Pages，国内手机连过去每秒几十 KB**。8 MB 就是两三分钟；就算砍到 4 MB，还是一两分钟。前面做的优化在 5 Mbps 下有效，在几十 KB/s 下只是"从 3 分钟到 1.5 分钟"。

## 二、四档路线

### A. 根治：资源放到国内（要你开账号，我来接）

把 `game-assets/`、`textures/`、程序文件放到国内对象存储（阿里云 OSS 或腾讯云 COS），页面还留在 GitHub Pages（页面本身只有 11 KB）；或者整站都搬过去。

- **为什么能根治**：国内 OSS 到手机每秒几 MB，8 MB 几秒下完，后面 B 档的所有优化才有意义。
- **不用备案**：用存储桶自带的域名（`xxx.oss-cn-xxx.aliyuncs.com`）不需要 ICP；只有绑自己域名 + 国内 CDN 加速才要备案。要自己域名再说。
- **费用**：存储 150 MB 几分钱/月；流量约 0.5 元/GB，一个人逛一圈下 10~30 MB，100 个人约 1~2 元。
- **你做**：开账号、实名、建一个公共读的桶、开 CORS（允许 `duamixu1.github.io` 来源 GET）、给我一对只能写这个桶的密钥放 `.env`（不进 GitHub）。
- **我做**：`build_site.py` 加 `--cdn` 上传 dist（按内容 hash 命名、长缓存），`paths.js` 的 `asset()` / `pub()` 按发布时写进 tour.html 的 base 走 OSS，OSS 拿不到自动回退 GitHub；glb 在 OSS 上没有自动 gzip，所以要配合 B2 先把模型压掉。
- **备选 jsDelivr**（`cdn.jsdelivr.net/gh/Duamixu1/strange_kitty@gh-pages/...`）：免费、不用开账号，单文件 50 MB 以内；但它在国内时好时坏（2022 年后几次被断），可以先试，别当唯一方案。
- Cloudflare / Vercel / Netlify 在国内都慢，不考虑。

### B. 少下东西（都是程序这边的活，不花积分，不用你开账号）

按省得多、做得快排：

| # | 做什么 | 省多少 | 怎么做 |
|---|---|---|---|
| B1 | **地铁人偶合一**：11 种 `mnq_*` 换成 1 个人偶网格 + 11 张小贴图（63 KB 一张） | 地铁 7.8 → 约 1.2 MB | `loadNpc` 加 `model` 相同、`tex` 不同的写法；一份网格 clone 多次换材质 |
| B2 | **积木 glb 压缩**：`kit_build.py` 出完跑 gltf-transform（draco 或 meshopt，npm 装，不用 brew） | 笛小路家 1.6 → 0.4，牢房 1.1 → 0.3，其余各省 0.2~0.3 MB | 发布时在 `build_site.py` 里做，源文件不动；draco 解码器已经在用 |
| B3 | **药郎减面**：10 万三角减到 4~5 万（衣服分层那部分最多） | 1.34 → 约 0.7 MB | 角色线 Blender decimate 保骨骼和 morph，不花积分；动作 30 个不动 |
| B4 | **道具合一 + 小贴图**：三件合成一个 glb，天秤 / 剑贴图 1024 → 512 | 0.8 → 约 0.3 MB，少 2 个请求 | 程序 |
| B5 | **纸纹只下一次**：CSS 那张改成和 JS 同样的拿法（或 JS 用 CSS 那张） | 省 0.35 MB | 一行 |
| B6 | **贴图换 WebP**：发布时 JPG/PNG 转 WebP（iOS 14 起都支持，老机器回退原图） | 装饰图再省 25~35%（约 6 MB → 4 MB 全站） | `build_site.py`，`kit.js` 按清单读 |
| B7 | **小贴图合图集**：每处几十张 10~60 KB 的小 PNG 合成一两张 | 请求数 55~77 → 约 30，高延迟下省几秒 | `kit_textures.py` 出图时合，UV 由 kit.js 偏移；改动大，排后 |
| B8 | **配角减面**：4.4~5.5 万三角 → 2.5 万 | 每个 0.4 → 0.25 MB，一处省 0.5~1 MB | 角色线，和 B3 一起做 |

B1~B5 做完：そらりす丸首次 8.5 → 约 4.5 MB，地下铁 12 → 约 4 MB。**在 GitHub 上还是慢（几十 KB/s 下 4 MB 要一分多钟），在 A 之后是 2~3 秒。**

### D. 先看真实数据（现在就能做，半天）

现在我只能在电脑上限速模拟，**不知道国内手机实际多少 KB/s**。加一条访问统计事件：每次加载完报 `load/<地点>/<档>`（档：<10 秒、10~30、30~60、60~120、>120）+ 手机还是电脑，再报铺垫页读了几页才"准备好"。GoatCounter 里一周就能看出：多少人在 1 分钟以上、A 做完掉到多少。
